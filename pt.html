SÉVÉRITÉ HIGH

À traiter en priorité — impact direct sur les données ou les utilisateurs si confirmé.

Certificat signé SHA1withRSA

SHA-1 est un algorithme de hash connu pour ses collisions.

high

VÉRIFIER

apksigner verify --verbose app.apk
keytool -printcert -jarfile app.apk

# Vérifier la présence de schémas v2/v3 en complément
apksigner verify --print-certs app.apk

Regarder la ligne Signature algorithm name. Si elle affiche SHA1withRSA, le finding est confirmé statiquement.

Impact réel : teste l'installation sur un device Android 10+ pour voir si un warning ou un refus apparaît. Si l'app a aussi un schéma v2/v3 (SHA-256), le risque réel est plus faible malgré le finding.

Padding Oracle — CBC + PKCS5/PKCS7

com/nimbusds/jose/crypto/impl/AESCBC.java:32

high

LOCALISER L'USAGE

jadx-gui app.apk
# Ouvrir AESCBC.java:32 et JCASupport.java:189
# → chiffrement réseau (JWE/JWT) ou stockage local uniquement ?

SI RÉSEAU — TESTER L'ORACLE

# Repérer d'abord le comportement serveur sur un ciphertext corrompu (Burp Repeater)
# puis :
padbuster https://target.com/endpoint "CIPHERTEXT_URL_ENCODED" 16 \
  -encoding 0 \
  -cookies "session=xxx" \
  -error "Bad padding"
Si aucun endpoint réseau ne fait ce déchiffrement, documente le finding comme théorique/local uniquement — la faiblesse de conception reste valide (CWE-649) mais l'exploitabilité à distance est nulle, à refléter dans la sévérité du rapport.

Cleartext traffic autorisé

Domain config permet du trafic HTTP non chiffré sur certains domaines.

high

IDENTIFIER LES DOMAINES CONCERNÉS

apktool d app.apk -o app_decoded
cat app_decoded/res/xml/network_security_config.xml
# Cherche <domain-config cleartextTrafficPermitted="true">

TESTER EN DYNAMIQUE

# Proxy Burp actif, naviguer dans toute l'app
# Burp → Proxy → HTTP History → filtrer les requêtes en http://

Vérifier si un des domaines listés dans le XML reçoit réellement des données sensibles (login, tokens, PII) en clair.

Impact réel : critique si des données sensibles transitent ; faible si le domaine ne sert qu'à un CDN d'assets statiques non sensibles.

App Link assetlinks.json manquant

host=https://mbapp.byblosbank.com — vérification App Links non effective

high

CONFIRMER L'ABSENCE DU FICHIER

curl -i https://mbapp.byblosbank.com/.well-known/assetlinks.json

PoC DE HIJACK

# Créer une seconde app de test avec le même intent-filter (host identique)
# puis déclencher le lien :
adb shell am start -a android.intent.action.VIEW -d "https://mbapp.byblosbank.com/reset?token=xxx"

Si un sélecteur d'application apparaît au lieu d'ouvrir directement l'app légitime, la vérification n'est pas effective.

# Confirmer aussi côté Manifest
grep -A 3 "autoVerify" app_decoded/AndroidManifest.xml
Impact réel : une app malveillante peut intercepter ces liens → phishing, vol de tokens OAuth ou de reset password.

App installable sur Android 7.0 (minSdk=24)

Devices anciens sans patchs de sécurité récents.

high

CONFIRMER

aapt dump badging app.apk | grep -i sdkVersion

Pas de test d'exploitation ici — c'est une faiblesse de configuration, pas une vulnérabilité active.

Documenter : minSdk actuel, recommandation (minSdk ≥ 29 / Android 10), et impact contextuel — la part réelle du parc utilisateur encore sur Android 7-9.

ATS AllowsArbitraryLoads (iOS)

App Transport Security désactivé pour toutes les connexions — équivalent iOS du cleartext Android.

high

EXTRAIRE ET LIRE L'INFO.PLIST

unzip app.ipa -d app_extracted
find app_extracted -name "Info.plist"
plutil -convert xml1 -o - app_extracted/Payload/*.app/Info.plist | grep -A 10 NSAppTransportSecurity

Confirmer la présence de NSAllowsArbitraryLoads = true sans NSExceptionDomains qui restreindrait le scope.

TEST DYNAMIQUE (si environnement dispo)

# Proxy Burp sur simulateur/device iOS, naviguer dans l'app
# Vérifier si du trafic HTTP non chiffré transite réellement
Nécessite un Mac + Xcode Simulator ou un device iOS physique. Sans accès iOS, documenter uniquement sur preuve statique (Info.plist) et le préciser dans le rapport.

À confirmer et documenter — impact généralement plus limité ou plus contextuel que les High.

Privacy Trackers

1 tracker détecté dans l'application.

medium

IDENTIFIER LE SDK

grep -riE "com.google.firebase.analytics|com.facebook.appevents|appsflyer|mixpanel" app_decoded/smali -r

Vérifier ensuite si ce tracker envoie des données dès le lancement, avant tout consentement utilisateur — surveille le trafic réseau dans Burp dès l'ouverture de l'app.

Impact réel = collecte avant consentement RGPD, à documenter si observé.

Secrets hardcodés

FCMService.java · PushConstants.java · PromptInfo.java · Card.java (Samsung Pay)

medium

RECHERCHE

grep -rEi "(api[_-]?key|secret|password|token|aws_access|BEGIN (RSA|EC) PRIVATE KEY)" app_decoded/ --include="*.smali" --include="*.xml"

# Outil dédié plus exhaustif
pip3 install trufflehog
trufflehog filesystem app_decoded/

Regarder en priorité les fichiers cités dans le rapport — souvent des faux positifs si c'est juste un nom de clé de config plutôt qu'un vrai secret.

medium

Random Number Generator faible

Diagnostic.java:21 · FCMService.java:43

medium 
grep -rn "new Random(" app_decoded/
grep -rn "SecureRandom" app_decoded/

Si new Random() génère un token, un nonce ou un ID de transaction (pas juste une animation UI) → confirmé, prévisible et exploitable. Sinon, impact faible.

Composants IPC exportés

Activities, Services, Broadcast Receivers partagés avec toute app du device.

medium

SETUP

adb push drozer-agent.apk /sdcard/
adb install drozer-agent.apk
adb forward tcp:31415 tcp:31415
drozer console connect

NON PROTÉGÉS — PRIORITÉ DE TEST

# PushInstanceIDListenerService
run app.service.send mobi.foo.byblos.mbanking com.adobe.phonegap.push.PushInstanceIDListenerService --action "test" --extra string key value

# FCMService
run app.service.send mobi.foo.byblos.mbanking com.adobe.phonegap.push.FCMService --action "test" --extra string key value

# ShareChooserPendingIntent
run app.broadcast.send --component mobi.foo.byblos.mbanking nl.xservices.plugins.ShareChooserPendingIntent --action "android.intent.action.VIEW"

PROTÉGÉS PAR PERMISSION NON DÉFINIE DANS L'APP

# PushHandlerActivity
run app.activity.start --component mobi.foo.byblos.mbanking com.adobe.phonegap.push.PushHandlerActivity

# ProfileInstallReceiver — android.permission.DUMP
run app.broadcast.send --component mobi.foo.byblos.mbanking androidx.profileinstaller.ProfileInstallReceiver --action "android.intent.action.MAIN"

# FirebaseInstanceIdReceiver — com.google.android.c2dm.permission.SEND
run app.broadcast.send --component mobi.foo.byblos.mbanking com.google.firebase.iid.FirebaseInstanceIdReceiver --action "com.google.android.c2dm.intent.RECEIVE"

# GenerateTapAndPayCredentialsService — SEND_ANDROID_PAY_DATA
run app.service.send mobi.foo.byblos.mbanking com.google.android.gms.tapandpay.issuer.GeneratePaymentCredentialsService --action "test"

OBSERVER

adb logcat | grep -i mbanking
Priorise les 3 composants non protégés — le plus fort potentiel d'exploitation réelle. Les composants protégés par une permission signature (souvent le cas pour Google/Adobe/Firebase) sont fréquemment des faux positifs.
